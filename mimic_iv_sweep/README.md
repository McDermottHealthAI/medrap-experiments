# mimic_iv_sweep

Systematic sweep over task scale, architecture variants, and hyperparameters
on MIMIC-IV, building on results from [`mimic_iv/`](../mimic_iv/) and
[`mimic_iv_smoke/`](../mimic_iv_smoke/).

All scripts use the post-refactor flat CLI (`medrap-train`, `medrap-preprocess`,
`medrap-prepare-retrieval-dataset`) and reuse the lab-shared tensorized cohort
at `/groups/mm6677_gp/data/MIMIC_MEDS/MEDS_cohort/processed`.

## Setup

```bash
cd mimic_iv_sweep
uv sync
```

This creates `.venv/` and installs `medrap` and all dependencies (including
`torch` and `nvidia-*-cu12` CUDA packages) from PyPI.

## Sweep design

### Phase 1 — Task-count sweep (`sweep_task_count.sh`)

Fixed architecture (RoPE encoder + cross-attention medium fusion, k=4, lr=1e-3,
3 epochs). Varies N ∈ {1, 2, 4, 8, 16, 32} to measure how jointly
training more prediction targets affects per-task AUROC.

N is kept small: task codes are sampled from a long-tailed clinical
vocabulary, and only a handful of codes (e.g. Blood Pressure, Weight, BMI)
have enough in-window positive volume for a stable per-task AUROC given the
current anchor-sampling scheme (see `scripts/check_task_balance.py`) --
requesting a large N mostly adds low-count, noise-dominated tasks rather
than signal.

### Phase 2 — Architecture ablation (`sweep_architecture.sh`)

Fixed N ∈ {1, 8, 32}. Compares three architectures:

| Variant | Description |
| --- | --- |
| `patient_only` | RoPE encoder → masked-mean pooling → head; no retrieval |
| `retrieval` | RoPE + cross-attention medium fusion, k=4 retrieved docs |
| `marginalized` | Same as `retrieval` but with `multitask_binary_bce_marginalized` loss |

### Phase 3 — Hyperparameter sweep (`sweep_hparams.sh`)

Fixed N=8, RoPE + cross-attention, 3 epochs. Full grid:
k ∈ {4, 8, 16, 32} × lr ∈ {1e-4, 1e-3, 3e-3} → 12 jobs.

### Phase 4 — Marginalized retrieval, random tasks (`sweep_marginalized_n1248.sh`)

See [below](#marginalized-retrieval-random-tasks-phase-4) for the full
architecture breakdown, exact run commands, and known caveats.

## Running the sweep

### Step 1 — Build the retrieval index (once)

```bash
cd mimic_iv_sweep
sbatch scripts/prepare_retrieval.sh
```

### Step 2 — Generate task labels for each N (once per N)

```bash
sbatch scripts/generate_labels.sh          # all 6 N values in parallel
# or a subset, e.g. only N=8 and N=32:
sbatch --array=3,5 scripts/generate_labels.sh
```

Label N values and their array indices:

| Index | N |
| --- | --- |
| 0 | 1 |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |
| 5 | 32 |

### Step 3 — Run the sweeps

```bash
sbatch scripts/sweep_task_count.sh
sbatch scripts/sweep_architecture.sh
sbatch scripts/sweep_hparams.sh
```

Phase 4 (`sweep_marginalized_n1248.sh`) has its own task-generation script and run
instructions — see [below](#marginalized-retrieval-random-tasks-phase-4).

Each script accepts extra arguments forwarded to `medrap-train` as Hydra
overrides:

```bash
sbatch scripts/sweep_task_count.sh training.trainer.max_epochs=5
```

## Marginalized retrieval, random tasks (Phase 4)

A focused run of the `marginalized` architecture (see Phase 2) over
N ∈ {1, 2, 4, 8} randomly-sampled tasks, using task labels generated by the
medrap task sampler after
[MedRAP#92](https://github.com/McDermottHealthAI/MedRAP/pull/92): task codes
are drawn uniformly at random from the train split's vocabulary, with **no**
positive-rate/count filtering. A sampled code can turn out rare or degenerate
(single-class) on a given split — that's now surfaced at training time via
`val/auroc/n_valid_tasks` vs `val/auroc/n_tasks`, not corrected for at
generation time.

### Architecture

Every stage below is a concrete config group under `src/medrap/conf/` in the
`medrap` package; values are what `sweep_marginalized_n1248.sh` sets.
`N` = number of tasks for that run (1, 2, 4, or 8).

| Stage | Module (`_target_`) | Config | What it does |
| --- | --- | --- | --- |
| **Encode** | `TimeDeltaRoPEPatientEncoder` (`encoder=rope`) | vocab 65536, embed dim 128, 4 heads, 2 layers, ff dim 256 | Transformer encoder over the patient's tokenized EHR event sequence; inter-event time gaps are injected via rotary position embeddings (RoPE) instead of absolute positions. Outputs `patient_state (B, S_ehr, 128)`. |
| **Query** | `SequenceMeanQueryProjector` (`query_projector=sequence_mean_1024`) | in 128, out 1024 | Mean-pools `patient_state` over non-padding sequence positions, linearly projects to a single 1024-dim retrieval query per patient (`R=1`). |
| **Retrieve** | `load_hf_dataset_retriever` (`retriever=hf_dataset`) | k=4, dataset = `data/retrieval_db` (built by `prepare_retrieval.sh` from `MedRAG/textbooks`) | FAISS similarity search of the query against precomputed document embeddings; returns the top-4 documents' tokens, attention masks, and key embeddings (`doc_key_embeddings`, required for marginalization scoring below). |
| **Retrieval-encode** | `TokenFeatureRetrievalEncoder` (`retrieval_encoder=token_feature`) | vocab 151936, embed dim 64 | Plain embedding lookup (no transformer) over each retrieved document's token ids. Outputs per-token document features `(B, 1, K=4, S_doc, 64)`. |
| **Fuse** | `PerDocCrossAttentionFusion` (`fusion=cross_attention_perdoc_medium`) | d_model 256, 8 heads, ff dim 512, 2 layers, dropout 0.1 | Expands the batch to `B×K`; for each of the 4 retrieved documents independently, the patient sequence cross-attends to that document's token features across 2 stacked cross-attention layers (residual + LayerNorm + FFN each), then mean-pools over the patient sequence. Outputs one 256-dim vector **per retrieved document**: `(B, K=4, 256)`. This per-document (not pooled-once) output is what makes marginalization possible at any `K`. |
| **Predict** | `LinearHead` (`head=linear`, in 256, out N) | — | Applied independently to each of the 4 per-document vectors → `per_doc_logits (B, K=4, N)`. Retrieval scores are recomputed differentiably (query · doc key embedding) → `differentiable_doc_scores (B, K=4)`, so the retriever receives gradients too. |
| **Loss** | `MultiTaskBCEMarginalizedLoss` (`training/loss=multitask_binary_bce_marginalized`) | num_tasks = N | REALM-style: for each (patient, task) pair, marginalizes the per-document `sigmoid(per_doc_logits)` over the 4 retrieved docs, weighted by `softmax(differentiable_doc_scores)`, then takes standard BCE against that marginal probability (NaN targets excluded). Gradients flow through the marginalization into the retriever, so retrieval is trained end-to-end alongside the encoder and head. |

Everything else matches `sweep_architecture.sh`'s `marginalized` arm:
`pooling=masked_mean` is set but unused on this path (`RetrievalAugmentedModel`
skips pooling entirely when `marginalized_retrieval=true` — see
`src/medrap/model/model.py`), 3 epochs, `lr=1e-3`, batch size 32,
`max_seq_len=256`, `seq_sampling_strategy=to_end`.

### Known caveat — validation AUROC may not reflect what the loss trains

`sweep_architecture.sh`'s existing `marginalized` runs at N=25/100 show AUROC
0.45–0.64 in W&B (`sweep-arch-marginalized-n25`/`n100`) — worse than or barely
above `patient_only`/`retrieval` at the same N — and its N=1/8/32 attempts
(2026-07-17) failed outright (silent kill after data loading, looks like an
OOM specific to this job class).

Tracing `RetrievalAugmentedModel.forward()` (`src/medrap/model/model.py`)
surfaced a likely explanation for the bad AUROC specifically: the model's own
`logits` output — the field validation AUROC is computed from
(`multitask_auroc_torch(targets, predictions.logits)`) — is built by
`_marginal_class_probabilities`, which takes a **`softmax` over the task
dimension** of `per_doc_logits`. That's correct for a single `C`-way
mutually-exclusive classification head, but wrong for `N` *independent*
binary tasks: it forces the `N` per-task scores to compete and sum to 1
instead of each getting its own calibrated probability. `training/loss` uses
the correct math (per-task `sigmoid`, straight from `metadata["per_doc_logits"]`,
never touching `predictions.logits`), so the loss the retriever is actually
optimized against is unaffected — but if this hypothesis is right, validation
AUROC is scored on a different, broken quantity than what training optimizes,
which would produce exactly the near-random-to-mediocre AUROC observed
without necessarily meaning the model failed to learn. Not fixed here — this
PR's runs are a chance to check `train/loss` against `val/auroc/mean` and
confirm or rule this out before touching `medrap` core.

### How to run

```bash
cd mimic_iv_sweep
sbatch scripts/prepare_retrieval.sh                 # once, if data/retrieval_db doesn't exist yet
sbatch scripts/generate_labels_n1248.sh              # N=1,2,4,8 task labels (array indices 0-3)
sbatch scripts/sweep_marginalized_n1248.sh           # marginalized retrieval, N=1,2,4,8
```

Each accepts extra `medrap-train`/`medrap-preprocess` Hydra overrides, e.g.
`sbatch scripts/sweep_marginalized_n1248.sh training.trainer.max_epochs=5`.

Per-task AUROC is logged every validation pass
(`training.module.validation_auroc_log_per_task=true`), not just the mean, so
results can be inspected per sampled task afterward — pull `val/auroc/task_{i}`
from W&B (run names `marginalized-n{N}-*`) alongside `val/auroc/mean` and
`val/auroc/n_valid_tasks` vs `val/auroc/n_tasks`.

Outputs land at `outputs/marginalized_n1248/n{N}/` (checkpoints + W&B run),
separate from Phase 2's `outputs/architecture/`.
